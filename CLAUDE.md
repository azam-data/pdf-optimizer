# PDF Optimizer

Offline PDF compressor for Windows: GUI + CLI, built with PyInstaller.
Users compress confidential bank PDFs, so correctness beats size.

## Layout
- pdfopt_core.py: the engine (images, fonts, scan mode, OCR, verification)
- pdfopt_batch.py: folder mode; app_gui.py: tkinter GUI; app_cli.py: CLI
- pdf_optimizer.spec: PyInstaller build; .github/workflows: Windows build + tests
- notebooks/: generated from the engine; never edit them by hand
- docs/ROADMAP.md: the review (task IDs E1, Q1, M1, S1, F1 ...)
- docs/TASKS.md: the task queue, in order

## Commands (macOS, after `source .venv/bin/activate`)
- Tests: `python -m pytest -q`
- Regenerate notebooks: `python tools/build_notebooks.py` (exists after task P0.3)

## Rules
1. One task per session. Do only the task you were given.
2. Test first: write a test that fails, then fix the code until it passes.
3. The whole suite must pass before you commit.
4. Never commit PDFs, and never read files outside this repository.
   Test PDFs are generated by tests/make_samples.py.
5. Do not change thresholds or default settings unless the task says so.
   If results change, update tests/baseline.json in the same commit and say why.
6. No new dependencies, and nothing that grows the Windows build,
   unless the task is about that.
7. Keep Windows behaviour: subprocesses use CREATE_NO_WINDOW; paths must work
   with spaces and non-English characters. Do not modify third_party/ binaries.
8. After changing pdfopt_core.py, regenerate the notebooks.
9. Commit message: "<TASK ID>: <what changed>".
10. When done, tick the task in docs/TASKS.md. If blocked, add a line to docs/BLOCKED.md
    that starts with the task ID, then the reason; commit it and stop.

## Tool use in unattended runs
- Run Python only as `python -m pytest ...`, `python tools/build_notebooks.py` or `python tests/make_samples.py` (no other scripts; check things with pytest instead).
  Never use `python3`, `.venv/bin/python`, `source`, or inline `python -c` / heredocs.
- Do not create other scripts to run, and never write to /tmp.
- To inspect files (including notebooks) use the Read and Grep tools, not shell scripts.

## Batch mode (queue v2)
- Only a task whose line in docs/TASKS.md contains [baseline] may update tests/baseline.json, with
  `python -m pytest tests/test_baseline.py --update-baseline`. Do it only after the fix is done and all other
  tests pass. In the commit message, list which samples changed and why. Other tasks must never change it.
- Do not stop for judgement calls. Choose the most conservative option (keep more content, accept a smaller
  saving), add one line to docs/DECISIONS.md starting with the task ID (what you chose, the alternative, why),
  commit it with the task, and carry on. Use docs/BLOCKED.md only when the tests cannot be made to pass.
- When a known-bug test marked xfail for your task starts passing, remove its xfail mark.
